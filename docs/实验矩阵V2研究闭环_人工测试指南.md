## 一、启动（★ 必须起**两个**服务，开两个终端）

| 服务 | 地址 | 作用 |
|---|---|---|
| **网关**（必需） | `http://127.0.0.1:8765` | 提供**全部 API** |
| **React dev**（必需） | `http://127.0.0.1:5173` | 提供前端资源，并把 API 请求**代理**到 8765 |

**终端 1 —— 网关**

```bash
cd /d/coding/powerMcp_Pskills/gateway && ./run_gateway.sh
```

看到 `Uvicorn running on http://127.0.0.1:8765` 即成功。
顺手核对启动日志里 `fence = D:/coding/...`（必须是这个形态）。

**终端 2 —— 前端**

```bash
cd /d/coding/powerMcp_Pskills/frontend && npm run dev -- --port 5173 --strictPort
```

打开 **<http://127.0.0.1:5173/>** → 点顶部「**实验矩阵**」。

> ★ **为什么必须起两个（不是配置错误）**：
> Vite dev 只给前端资源 + **代理** API，数据全部来自网关。
> **只起 Vite** → 页面会如实提示「**网关没在跑**」（起上网关刷新即可）；
> **只起网关** → **不能**用 `http://127.0.0.1:8765/ui/`（网关挂的是**前端源码目录**，`index.html` 引
> `/src/main.tsx`，TSX 源码浏览器执行不了）→ 必须由 Vite 编译。
> 设计 §八「仅绑 `127.0.0.1`」**已满足**；§九 的「FastAPI 单进程 serve 构建产物」是**目标形态，当前未落地**。

> ⚠️ 「实验矩阵」页有**两个**新建入口，别搞混：
> **「新建实验」= V1**（直接登记网格）· **「新建提案」= V2（本次要测的就是它）**。

## 二、测试清单（A–G，全在界面上点）

### A. 新建提案

| # | 操作 | 预期 |
|---|---|---|
right | A1 | 点「**新建提案**」 | 展开表单：标题 / 研究问题 / 假设 / 算例 / 执行步骤(JSON) / 因子(JSON) |
right| A2 | 研究问题填「case39 与 case118 的规模指标？」；假设填「case118 母线数更大」 | — |
right| A3 | 勾选 **`IEEE39`** 与 **`case118 (判据#1 验收)`** | 两行都打勾（可多选） |
right| A4 | 「执行步骤」整段替换为下方 JSON | — |
right| A5 | 「因子」保持 `[]` | — |
right| A6 | 点「**生成并校验提案**」 | 卡片下方出现「提案 `proposal-xxxx` · 网格 **2** 格」「校验：**通过**」，并出现 Commit 按钮 |
| A7 | 看卡片下方「**已有提案（N）**」 | 每个提案一行：标题 · `proposal-xxxx` · 步数 · 状态（未提交 → 有「**提交**」；已提交 → 显示 `已 commit → exp-xxxx`）· 「**删除**」 |

> ★ **提案可以累积多个**（不是「只能建一个」）：建完一个可继续改表单再建下一个；
> 清单会列出**全部**提案，可逐个「提交」或「删除」（删除只移除提案，**不影响已 commit 的实验**）。
> 点「**清空表单**」一键重置；**Commit 后表单也会自动重置**（避免因内容未变而重复命中同一个提案）。

**A4 要粘贴的内容**（实测可跑）：

```json
[
  {"server": "surge", "tool": "load_network", "args_template": {"file_path": "{case_path}"}}
]
```

### B. Commit（冻结定义）

right 点「**Review 后 Commit（冻结定义）**」。

**预期**：顶部提示「已 commit V2 实验 `exp-xxxxxxxx`，定义已冻结」；左侧列表出现该实验
（id 以 **`exp-`** 开头，副标题显示 `surge.load_network`）。

> ★ 关键：**A6 通过后不会自动 commit** —— 必须再点一次这个按钮。这就是"提案 ≠ 执行"。

✔### C. 串行执行

点左侧那个实验 → 详情区点「**串行执行**」→ 等几秒（会真实拉起引擎）。

right **预期**：网格里每格状态变 **completed**；按钮在执行期显示「执行中…」且不可重复点。

### D. 刷新结果表

点「**刷新结果表**」。

right  **预期**：网格出现指标列 ——

| 指标 | 第 1 格（case39） | 第 2 格（case118） |
|---|---|---|
| `metric.results.name` | case39 | case118 |
| `metric.results.n_buses` | **39** | **118** |
| `metric.results.n_branches` | 46 | 186 |


> 指标键统一带 `metric.` 前缀（内核加的命名空间，防止与保留列 `status` 撞名）。
> 假设被数据支持：母线数 39 → 118。

### E. 两步 N-1（有状态步骤序列 —— V2 的真正价值）

再建**一个**提案（同 A1–A5），只是：

- 算例**只勾 `IEEE39`**；
- 「执行步骤」换成：

```json
[
  {"server": "surge", "tool": "load_network", "args_template": {"file_path": "{case_path}"}},
  {"server": "surge", "tool": "run_n1_branch_contingency", "args_template": {}}
]
```

然后 Commit → 串行执行 → 刷新结果表。

**预期**：**1 格 completed**，指标为

```
metric.results.n_contingencies    = 46
metric.results.n_with_violations  = 23
metric.results.n_violations       = 52
```

> 这两步**必须落在同一个引擎进程**（`load_network` 装进的网络给下一步用）——所以网关要求
> 一个实验的所有步骤**同一个 server**，且必须开会话池（启动脚本已设）。

> ★ **「已复用」只在同一提案重复提交时出现**（2026-09-28 裁决后语义）：`eid` 由
> 「**提案** + 算例 + 因子 + 步骤」派生 —— **每个提案是一个独立的实验配置**，即使执行步骤
> 与已有实验完全相同，也会得到**独立的新实验**（可独立运行、导出、分析）。
> 只有**同一个提案**点第二次 Commit 才会复用（HTTP 200 + `reused: true`，幂等不重跑）。

## 五、环境坑（3 条）

1. ⚠️ **dev 必须带 `--strictPort`** —— 否则 5173 被占用时 Vite 会静默换到 5174/5175，你打开的可能是残留实例。
2. ⚠️ **`{case_path}` 是网关内置占位符，原样写** —— 不要替换成真实路径（网关会自己填）。
3. ⚠️ **多步实验必须开会话池**（`run_gateway.sh` 已设）—— 若「串行执行」返回 503，说明池没开，那是**设计内的 fail-closed**，不是 bug。

## 六、修复记录（2026-09-28：按上面标记修复）

> 张老师按本指南测出的两个问题**均已修复并真机验证**。**原始标记保留在上文**（测试证据）。

### F-V2-2 · 导出 CSV / Markdown 报「实验不存在」（对应 §二-F 的 `wrong`）

| 项 | 内容 |
|---|---|
| **根因** | `GET /experiments/{eid}/export` 只走 V1 的 `_load_for_read`，**没有 V2 分支**；而 `GET /results` 有 ⇒ 同一个 V2 实验「**看得见表、导不出来**」 |
| **修复** | 抽出 `_v2_results_report()`，`/results` 与 `/export` **共用**（避免两处各写一遍而漂移） |
| **验证** | V2 两个实验 `format=csv\|md` 均 **200**；V1 实验无回归（全量 **652 passed**） |

### F-V2-3 · 结果表看不到 `n_buses`（对应 §三 判定 #4 的 `N`）

| 项 | 内容 |
|---|---|
| **现象** | 网格行内只显示 `areas.count / base_mva / freq_hz / n_areas`，看不到 `n_buses` |
| **根因** | 网格行内**只给 4 项**（`INLINE_METRIC_LIMIT`），按「数值优先 + 字母序」取前 4 ⇒ `n_buses` 排第 5 被截断；而那句提示「**见结果表**」**指向一张并不存在的表**（UI 从未渲染 `/results` 的完整列） |
| **修复** | 新增 `ResultTable` 组件（UI 规范 §4.7.4 里已规划但一直未实现），在网格下方渲染**全部列** |
| **验证** | 真机确认结果表 **28 列**、含 `metric.results.n_buses` = **39 / 118**（前端 **182 passed / 9 文件**） |

### F-V2-4 · 两步 N-1 提案 Commit 报 400「不可变实验已存在且定义不同」（对应 §二-E 实测报错）

| 项 | 内容 |
|---|---|
| **现象** | 按 §二-E 新建两步 N-1 提案 → Commit → `HTTP 400：不可变实验已存在且定义不同：exp-784b21d0d1444637` |
| **根因** | `eid` 只由「算例内容 + 因子 + 步骤序列 + 编译器版本」派生（**不含 title / research**，规格 §10.2 要求身份不依赖措辞），但**不可变性检查比较的是整个 `definition.json`** —— 而它含 `provenance.proposal_id = H(整个 payload)`，**必然不同** ⇒ **同一个执行定义下，任何新提案 commit 都必然 400**。这是死路：用户既跑不动，又从错误信息里看不出差在哪 |
| **修复** | 冲突判定改为只比**执行身份**（新增 `_execution_identity()`，与 `_eid()` 构成**严格一致**）；元数据（标题/研究问题/observables/analysis/provenance）差异 → **复用**既有实验并返回 `reused: true`（HTTP 200）；只有执行内容**真不同**才拒绝 |
| **验证** | 真机：**无错误横幅**、提示「已复用 V2 实验 `exp-784b21d0d1444637`」、刷新结果表**直接看到 46 / 23 / 52**（同一执行定义 = 同一实验，结果已存在，无需重跑）；网关 **655 passed** |

> ★ **语义已按 2026-09-28 裁决修订**：`eid` 现由「**提案** + 算例 + 因子 + 步骤」派生 ——
> **每个提案是一个独立的实验配置**。F-V2-4 的 400 死路以更彻底的方式消失：
> 不同提案（即使执行定义完全相同）→ **不同 eid 的独立实验**（各自 201），不再折叠、不再复用；
> 只有**同一提案**重复 Commit 才复用（200 + `reused: true`，幂等）。
> 真正冲突（同 eid 但执行内容不同，如 `definition.json` 被手工改过）**仍会被拒绝**（有测试钉住）。

### F-V2-6 · 提案「只能新建一个，要建新的得先删旧的」（2026-09-28 反馈）

| 项 | 内容 |
|---|---|
| **现象** | 建了一个提案后无法再新增第二个 —— 体验上「系统只允许新建一个提案」 |
| **根因** | **后端其实一直支持多提案**（`ProposalStore` 早就有 `list()` / `delete()`），但**缺两个出口**：① **`GET /experiment-proposals` 列表端点不存在**；② **没有 DELETE 端点**。前端只有一个 `proposal` 单值 state ⇒ 建第二个会**覆盖**第一个的预览；commit 后**表单不重置**，再点「生成并校验」会因内容未变而命中同一个提案。⇒ **看不到、删不掉、存不住**，体验上就是「只能有一个」 |
| **修复** | 后端加 `GET /experiment-proposals`（列表，含 `committed_eid`）与 `DELETE /experiment-proposals/{id}`（**只删提案，不删已 commit 的实验**）；前端提案卡新增「**已有提案（N）**」清单（逐个 提交 / 删除）+「**清空表单**」+ commit 后自动重置表单 |
| **验证** | 真机：清单显示全部提案、新建后 **+1**、删除后 **−1**、已提交的显示 `eid`；网关 **656 passed**、前端 **187 passed / 9 文件** |

> 复测建议：重跑 §二-A / §二-D / §二-E / §二-F ——
> **A** 提案卡下方应出现「**已有提案（N）**」清单（可累积多个、逐个提交/删除）；
> D 应看到网格下方的「**结果表（完整指标列）**」；
> E 用**与已有实验相同的算例+步骤**再建一个新提案，应得到**独立的新实验**（新 `eid`，201），
> 各自运行 / 结果 / 导出互不影响（2026-09-28 裁决：每个提案 = 一个独立实验配置）；
> F 点导出应直接下载文件（`experiment-<eid>.csv` / `.md`）。
