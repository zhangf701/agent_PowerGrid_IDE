## 一、启动（三步）

### 1. 起网关（8765）

```bash
cd /d/coding/powerMcp_Pskills/gateway && ./run_gateway.sh
```

看到 `Uvicorn running on http://127.0.0.1:8765` 即成功。

> 脚本已自动设置 **路径围笼**（`POWERIO_MCP_ALLOWED_ROOTS`）与
> **会话级连接池**（`POWERMCP_SESSION_POOL=1`）。
> ⚠️ 多步实验**必须有**会话池，否则 `/run` 会返回 503 —— 那是设计内的 fail-closed，不是 bug（见 §四-2）。

### 2. 起前端 dev（**另开一个终端**）

```bash
cd /d/coding/powerMcp_Pskills/frontend && npm run dev -- --port 5173 --strictPort
```

看到 `Local: http://localhost:5173/` 即成功。

> `frontend/vite.config.ts` 已固定 `host: "127.0.0.1"`，因此开发服务器会绑定 IPv4；
> 修改该配置后必须重启 Vite 才生效。若终端仍显示旧进程，先停止旧实例再重新启动。
>
> ⚠️ **务必带 `--strictPort`**：不加的话，5173 被占用时 Vite 会**静默换到 5174/5175**，
> 而你还是打开 `localhost:5173` —— 命中的是**另一个（可能是残留的）实例**，
> 排查方向会完全跑偏（2026-09-27 实测踩过：残留实例的代理指向没在跑的网关 → 满屏 `HTTP 500`）。
> 带 `--strictPort` 时端口被占用会**直接报错退出**，比静默换端口安全。
> 若真被占用：先查 `netstat -ano | findstr :5173`，确认那个 PID 是不是该关掉的旧实例。

> ⚠️ **不要用 `http://127.0.0.1:8765/ui/`**：网关挂的是**前端源码目录**，
> 而 `frontend/index.html` 引的是 `/src/main.tsx`，必须由 Vite 编译才能跑。
> dev 模式会把 `/experiments`、`/cases` 等路径**代理到 8765**（同源，无 CORS）。

### 3. 打开

浏览器访问 **<http://localhost:5173/>**

I2 —— 并发两个 `/run`：

```bash
EID=<你的实验 id>
curl -s --noproxy '*' -o /dev/null -w "req1=%{http_code}\n" -X POST http://127.0.0.1:8765/experiments/$EID/run &
sleep 0.3
curl -s --noproxy '*' -o /dev/null -w "req2=%{http_code}\n" -X POST http://127.0.0.1:8765/experiments/$EID/run
wait
```

I3 —— 同会话并发两次调用：

```bash
SID=$(curl -s --noproxy '*' -X POST http://127.0.0.1:8765/sessions \
  -H "Content-Type: application/json" -d '{"servers":["surge"]}' \
  | python -c "import sys,json;print(json.load(sys.stdin)['id'])")
for i in 1 2; do
  curl -s --noproxy '*' -o /dev/null -X POST "http://127.0.0.1:8765/sessions/$SID/tools/call" \
```

## 四、已知预期行为（**不是 bug**）

1. **旧格式实验会列出但不可执行**。默认实验库里有 1 个 `N-1 扫描（e2e）`，它是 **2026-09-27 之前**的记录
   （当时实验只支持单步 `server`/`tool`，没有 `steps`）。它在网格里显示为**空步骤链**；点「串行执行」会返回
   **409** +「该实验没有步骤（定义为空）…请按 `steps[]` 重新登记」。
   —— 这是**刻意**的 fail-closed：若放行，`execute_cells` 的步骤循环不跑，格子会得到「成功」且 0 步，
   即**「跑了 0 步却说成功」的假绿灯**。
2. **多步实验需要会话池**：若网关没设 `POWERMCP_SESSION_POOL=1`，`/run` 返回 **503** 并给出修复路径。
3. **深链只在全新加载生效**：`#experiments/<eid>` 在挂载时读一次；同一页面内改 hash 不会切换实验
   （与既有 `#skills` 深链同一行为）。切换请刷新。
4. **池开启时 `leases.waited` 可能为 0**：连接池的每条连接**本身就是队列串行**
   （`_Conn._run`：专属 task 持有上下文、队列串行接活），同一会话的两次调用在池内就已排队。
   租约真正起作用的是**无池**路径。
5. **`/results` 是格级对比表**，不是越限明细表。越限明细级的 `result_tables` 透视（模块列定义 / G-2 pivot）
   属 **P3**，尚未实现 —— 不是漏了。
6. **行内只显示前 4 项指标**（数值优先），其余以「共 N 项指标，见结果表」明示 —— **截断可见**，不是漏显示。
7. **未引用因子会产生重复格**（各格 `cache_key` 相同，跑一遍等于跑多遍同样的事）—— 网关会告警，界面会显示该告警。
   这是如实行为：因子只有在被模板引用时才改变实验条件。
8. **首次执行要真实拉起 MCP server**（秒级到十几秒）；未配置的 server（andes/egret/hope/genx…）拉不起来属正常。
9. **并发开关未打开**：实验执行仍是**串行**的（方案 §4.4 裁决）。本步只是把并发化的**前置条件**补齐。
   租约是**进程内**的，跨机文件租约未实现 —— 不要据此认为"并发已完全安全"。
