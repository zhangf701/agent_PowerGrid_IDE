## 三、★ 关键发现：绑定键不能叫 `on`

清单绑定 `checks[].on: rt1` 时 YAML 1.1 会把裸键 `on` 解析成布尔值 `True`
（`{True: 'rt1'}`）—— 本仓库在 `id: on` 上踩过同一个坑并写进了诊断信息。
绑定会**静默失效**（校验找不到 `on` 键 → 当作未绑定）。故绑定键定为 **`result_table`**，
并在清单模板与 checks.py 契约文档里写明原因，另加测试 `test_g5_bare_on_key_is_boolean_trapped_so_we_use_result_table` 钉住。

## 五、坑（全部实测踩到）

1. **heredoc 吞 `\n` 第三次复现**（交接单明文记载仍踩）：两次用 heredoc 写 Python/YAML
   都产生字面 `/n`。**结论升级为铁律：任何含转义的脚本一律写成文件**（本次连测试追加持也都改走 Edit 工具）。
2. **YAML 裸键 `on` = 布尔值**（见 §三）。
3. **变异探针的备份恢复必须在每个变异后立即核验**：m22 首版统一在结尾恢复，
   结果 checks.py/api.py 残留变异态且未被察觉（下游锚点失配的表象极具误导性）。
   已改为"每变异 → 立即恢复 → 立即断言还原"。
4. **`_write_prompt_module` 类助手会自己拼目录名** —— 调用方再拼一次就双层嵌套，
   glob 找不到清单 → "无模块"而非报错（fail-silent 陷阱，靠打印目录树定位）。
5. chat 测试存在**真实 `modules/` 环境泄漏**：`/chat` 现在会注入模块提示词，
   所有 chat 消息序列断言都必须把模块根隔离到空目录（`_setup(modules_root=…)`）。
