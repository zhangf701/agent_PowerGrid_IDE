## 二、安装范围决策

初次尝试安装了全集 `.[opensource]`（7 个开源 extra）。经与用户确认后**收窄**为：

> **核心 + `[hope,surge]`**

### 决策依据：核心不可省，extra 完全可选

`pip install -e .`（不带 extra）**强制**带入：

| 包 | 角色 |
|---|---|
| `pandapower` | 核心 |
| `pypsa>=0.35.2,<2` | 核心 |
| `powerio[mcp,matrix]>=0.11.2,<0.12` | **跨 server 交换格式的提供方** |
| `mcp>=2,<3` | 每个 server 都要 |
| `typer`/`rich`/`questionary`/`tomli-w`/`tomlkit`/`packaging` | CLI 工具链 |

可选 extra 及其实际拉取内容：

| extra | 实际拉取 | 重量 | 本次 |
|---|---|---|---|
| `andes` | `andes` | 中 | ✗ 不装 |
| `egret` | `gridx-egret` + **`pyomo`** | 重 | ✗ 不装 |
| `opendss` | `py_dss_toolkit` | 中 | ✗ 不装 |
| `ltspice` | `PyLTSpice` + `matplotlib` | 中 | ✗ 不装 |
| `surge` | `surge-py>=0.1.5` | 重（pyo3/maturin 轮子，限 py3.12–3.14） | **✓ 装** |
| `hope` | `PyYAML>=6.0` | 极轻 | **✓ 装** |
| `genx` | `matplotlib` + `pandas` | ≈0（核心已带） | ✗ 不装 |

> **`genx` extra 不增加任何新包** —— `matplotlib`/`pandas` 由核心的 pandapower 传递带入。此结论已由实测证实：未装 `genx` extra，但 `powermcp doctor` 对 genx 显示 `ok`，且 venv 中确实存在 `matplotlib 3.11.2`。

### 实现方式：重建而非卸载

选择**删除并重建 venv**，而非逐个 `pip uninstall`。原因：`matplotlib`/`pandas` 等包既有 extra 带入的、也有核心传递带入的，逐个卸载易留下孤儿包或误删核心依赖。重建保证环境恰等于声明的依赖集；uv 有下载缓存，重建成本低。

## 五、当前可用能力与限制

### 可用（3 个 server 开箱可用）

| server | 工具数 | 前置条件 |
|---|---:|---|
| pandapower | 8 | 无 |
| PyPSA | 17 | 需 LP/求解器在 PATH（HiGHS / CBC / GLPK / Gurobi） |
| PowerIO | 10 | 无（转换、矩阵、诊断） |
| surge | 44 | 需系统库 HiGHS + Ipopt（**非 pip 可装**） |

### 装了但跑不动

| server | 缺什么 |
|---|---|
| HOPE | Julia 运行时 + HOPE 仓库本体（`hope.repo_root` / `hope.julia_bin`） |
| GenX | Julia + GenX.jl checkout（`genx.repo_root`） |

> 这是 PowerMCP 的普遍模式：**装得上 ≠ 跑得动**。闭源/外部引擎的 server 在包层面可导入，但真正调用工具时才报错（延迟导入 + 可操作报错，无 mock 降级路径）。
