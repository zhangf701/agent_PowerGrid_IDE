## #6 围笼拦截（反向）——✗，已坐实为待诊断 bug（不是测试操作失误）

- **现象**：登记 `C:\Users\Z\Downloads\_科研项目\case5.m`（项目根之外）→
  预期 409「不在允许根内」，实际 `/cases → HTTP 400：算例文件不存在`。
- **当天已核实的事实链**（张老师确认文件当时存在 + 助手复查）：
  1. 文件真实存在：`ls` 命中；mtime `2025-05-29`，远早于测试时刻；
  2. 网关同款解释器（`PowerMCP/.venv` Python 3.12）对该路径
     `exists()=True / is_file()=True`；
  3. 代码链路逐环排查均应放行"正确字符串"：前端 `casePath.value.trim()`
     （mvp.html）→ 服务端 `_parse_case_request` 的 `raw.strip()`（api.py:612）
     → `cases.py::register` 的 `src.exists()` 检查（cases.py:254）。
- **推断**：到达网关的路径字符串与预期不一致（最可疑：输入混入不可见字符 /
  全角字符 / 引号——400 的 error echo 在视觉上无法分辨这几类差异）；
  或网关进程运行环境存在差异。**存在性检查对真实存在的文件误报，围笼反向
  拦截（409 分支）至今未被真正触发验证。**
- **待做二分复现**（网关开着时，一条命令定位在哪一侧）：
  ```bash
  curl -s -X POST http://127.0.0.1:8765/cases -H "Content-Type: application/json" \
    -d '{"path":"C:\\Users\\Z\\Downloads\\_科研项目\\case5.m"}'
  ```
  返回 200/201 ⇒ 问题在浏览器输入侧（IME/剪贴板引入脏字符）；
  仍 400 ⇒ 问题在网关运行时（查网关终端日志 + 进程环境）。

## #8 契约拦截——未完成（A 方案记法：对话路径不适用，待 curl 路径 B 补测）

- 对话路径两次尝试均未产生 `contract_violation`：
  - 示例 1（缺 `file_path`）被模型以「客户端 SDK 会先做 schema 校验」为由拒绝
    ——**该理由已被源码证伪**：Agent 循环在网关侧（张老师 2026-09-25 裁决），
    `agent.py::_parse_args` 仅做 `json.loads`，`llm.py` 调 LLM 未开 strict，
    缺参调用会原样到达 `proxy.call_tool` 即契约 3；
  - 示例 2（`pypsa.run_power_flow` + `linearized=true`）被模型改道为
    `surge.load_network`（返回结构比对确认）。
- **结论**：`missing_required` / `unknown_arg` 靠对话触发**不可靠**（模型被训练为
  发出合法调用，会拒绝、修正或改道）；确定性路径 =
  `POST /sessions/{sid}/tools/call`（同走 `call_with_contracts`，api.py:437），
  命令与预期响应见 `docs/MVP测试_契约拦截示例.md` 路径 B。
- 对 React 版的启示：契约拦截的端到端测试应以 HTTP 直构为准绳，
  对话触发只作演示，不应写进验收清单。
