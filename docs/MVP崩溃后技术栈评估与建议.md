# MVP 崩溃后：是否回到正式技术栈的评估与建议

> 2026-09-26 · 触发事件：调试 MVP 过程中发生一次崩溃；MVP 目前部分功能可用、整体显示正常。

## 一、结论（先说答案）

**建议：向正式技术栈（React + Vite + TS + Tailwind）迁移，但不是"立刻推倒重来"，而是分三步走。**
MVP 这次崩溃**不构成回退信号**，恰恰相反——它完成了它该做的事（把真实问题暴露出来）。
是否需要迁栈，判断依据不是"MVP 稳不稳"，而是"MVP 的验证使命是否已基本完成"。

## 二、现状盘点

### MVP（单文件 `frontend/mvp.html`）

| 项 | 状态 |
|---|---|
| 架构 | 单 HTML + 原生 JS + 生成物 `tokens.css`，零依赖零构建 |
| 已覆盖 | 环境就绪面板、算例登记/解析/注销、技能手册视图、SSE 对话流、校验层状态条、契约事件渲染、主题切换、自检/调试模式（`?selftest` / `?fullbody` / `?nosse`） |
| 当前健康 | **部分功能可用、整体显示正常**（用户口径）；发生过一次调试期崩溃，根因未记录 |
| 已知短板 | 无组件复用（~800 行单文件）；无类型约束（后端字段变更靠运行时踩坑）；无单测（只有自检合成事件）；状态管理靠全局变量；继续叠加功能会线性变慢变脆 |

### 正式技术栈（尚未起步）

- 设计系统已落地：`design/tokens.json` → `tokens.css` / `tokens.generated.js`，有 `--check` 双护栏；
- React 工程骨架、基础件（Button/Dialog/Toast/… §4.6）、研究视图组件（§4.7）均未开工；
- MVP 已在消费 `tokens.css`，说明令牌层与界面观感已被真实验证过一遍。

## 三、评估：崩溃说明什么

1. **崩溃发生在"调试中"，不是"使用中"。** 单文件 MVP 没有模块边界、没有错误边界，
   任何一处渲染异常都可能让整个页面挂掉——这是结构决定的，不是偶发质量事故。
2. **显示正常 ≠ 结构健康。** "部分功能可用"意味着部分功能不可用，且这次没有兜底
   （没有组件级隔离、没有自动测试把崩溃钉住），下次回归无从感知。
3. **随着功能增加（ANDES 已接入、后续诊断/实验网格），单文件的边际成本在快速上升。**
   §4.6/§4.7 规划的组件在 MVP 里全部是手写重复代码。
4. **MVP 已产出最大价值**：16 个端点的交互模式、SSE 帧解析、契约可视化的信息架构
   都已跑通并被人工看过——这正是迁栈前最需要的"需求证明"。

> 一句话：MVP 不是失败了，是**毕业了**。它该退役为参照物，而不是继续当主力。

## 四、建议路线图（分三步，可验收）

### 第 0 步（前置，1 次会话内）：给崩溃留个底

- 记录这次崩溃的现象与复现路径（若还能复现），至少写明"哪一步、什么报错"；
- 把 `docs/MVP人工测试指引.md` 的 10 条清单补测完，标注实际 ✓/✗ —— 这份结果就是
  **React 版的需求验收清单**。

### 第 1 步：React 骨架先行，不与 MVP 抢功能

- `package.json` / `vite.config.ts` / `tailwind.config.js`（import `tailwindTheme`）；
- 先做基础件（§4.6），再做研究视图组件（§4.7）；
- **MVP 保持可运行**（`/ui/mvp.html` 不动），作为对照与回退手段。

### 第 2 步：逐个视图从 MVP 迁移，一一比对

- 迁移顺序建议：技能手册（最独立、无流式）→ 算例库 → 对话 + 校验层（最复杂，最后做）；
- 每迁完一个视图，用 MVP 截图/行为做 A/B 对照；契约状态条、错误可见性
  （"不需要开控制台"）这两条验收判据原样保留；
- 保留 MVP 的调试模式思想：`selftest` 对应 React 版的组件级单测（Jest/Testing Library）。

### 第 3 步：React 版覆盖 MVP 全部验收项后，MVP 降级存档

- 不删除，移入 `frontend/legacy/mvp.html` 并注明"冻结，勿再改"；
- 无头验证链路（`--dump-dom` / `?fullbody=1`）的思路在 React 版重建。

## 五、不建议的做法

- ❌ **立刻冻结 MVP 全面转向 React 从零开发** —— 会丢掉"人工测试已验证的交互细节"，
  且网关端还有未提交改动（`run_gateway.cmd/sh`），节奏上应先收口；
- ❌ **继续往 MVP 上加新功能**（诊断视图、实验网格等 §4.7 内容）—— 单文件已到承载上限；
- ❌ **因为一次崩溃就质疑单文件方案的初衷** —— 按张老师裁决"先人工测试再定后续"，
  现在正是"后续"的决策点，本文件即该决策的输入。
