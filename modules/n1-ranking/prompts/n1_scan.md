# N-1 关键故障排序 —— 扫描提示词

> 本文件由 `n1-ranking` 选题模块声明（`prompts[].file`）。
> ⚠️ **当前尚无引擎读取它** —— 网关的 `/chat` 不会自动加载模块提示词。
> 该接线是 P1 的工作；此处先把内容写实，以便接线后立刻可用。

## 目的

在**可复现**的流程下得到带数值的 N-1 关键故障排序，并验证其物理自洽性。

## 提示词

```text
对算例 {case_id} 做 N-1 支路故障扫描，严格按下面顺序：

1. 先载入并检查模型（surge.load_network → surge.get_network_info）。
   报告母线 / 支路 / 机组 / 负荷计数与平衡机。
2. 跑基态直流潮流（surge.run_dc_power_flow），报告基态最大负载率。
   ⚠️ 基态不通过就不要做 N-1 —— 否则越限排序没有基准。
3. 跑 N-1 支路故障扫描（surge.run_n1_branch_contingency）。
4. 按负载率降序输出越限明细，**必须给数值与单位**，格式：`161.84% (MVA 判据)`。
5. 对 Top-3 越限元件，用 surge.compute_ptdf / compute_lodf 给出归因
   （哪个注入转移加剧了它）。
6. 结果写入 n1_results 结果表；导出报告用 n1-report 模板。

约束：
- **标识符必须标注编号约定**：如 `branch_26 (1-based)` —— 跨引擎比对时这是 3.1 亿倍偏差的来源。
- Islanding 类型的越限**没有支路定位信息**，必须单独标注为「孤岛」，不得当成"元件越限"。
- 不得跳过基态直接做 N-1。
```

## 已知陷阱（来自实测）

| 陷阱 | 表现 | 处理 |
|---|---|---|
| `Islanding` 类型无支路定位信息 | 越限明细里元件名为空 | 单独归类为孤岛，容错而非崩溃 |
| 编号约定 | 跨引擎比对张冠李戴 | 一律标注 `(1-based)` / `(0-based)` |
| 基态不收敛 | N-1 结果无意义 | 先跑基态，不通过即中止 |
